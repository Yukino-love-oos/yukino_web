# 拟人化设计：表情包 / 分条发送 / 心情衰减 / 记忆打分 / 三层人格

> 这五项不是「功能」，而是让机器人**像一个具体的人**而不是一个查询接口。
> 每项都写了「为什么这样做」和「参数怎么调」，方便以后改。

## 1. 表情包（P0）

### 做法

模型在回复末尾可选带一个标签：

```
<ja>なっ……違うわよ。</ja>
<zh>什……不是的。</zh>
<act>别过脸，耳根有点红</act>
<mood>shy</mood>
<aff>1</aff>
<sticker>shy</sticker>
```

- 标签名与**情绪同名**：`calm / tsundere / soft / angry / shy / tired`
  （一张情绪一张图，模型不用记两套词表）
- 图片在 `app/ui/assets/stickers/<name>.png`，由 `app/ui/assets/expressions/` 的立绘裁成 320×320
- 发送走 `file_type=1` + `msg_type=7`，**和语音共用同一条富媒体通道**（代码复用）
- 网页版：`/assets/<name>.png` 直接显示

### 为什么不做「每轮都发」

人设里明确要求：**5~8 条回复才用一次，不许连续发**。
表情包的价值在于「刚好那一下」，每轮都发就变成了骚扰。

### 容错

`_parse_sticker()` 认不出的名字**静默丢弃**，绝不把不存在的文件名传给发送端。
支持中文别名（「傲娇」「害羞」「生气」），因为模型经常写中文。

## 2. 分条发送（P2）

雪乃说话本来就短促（「ふん。」「……そう。」「別に。」），
一大段一次甩出去不像她，更像客服。

做法：按句末标点和换行拆成最多 3 条，每条间隔 0.6 秒。

| 参数 | 默认 | 说明 |
|---|---|---|
| `QQ_TEXT_PARTS` | 3 | 最多拆几条 |
| `QQ_TEXT_GAP` | 0.6 | 条间隔（秒） |

`msg_seq` 统一分配：文字 1..n → 表情包 → 语音依次递增
（QQ 被动回复要求同一个 `msg_id` 下 `msg_seq` 唯一）。

## 3. 心情衰减（P1a）

### 问题

只把 `<mood>` 存成字符串的结果是：**「上次聊天有点生气」会一直挂着**，
三天后说话她还在生气 —— 人不是这样的。

### 模型

```
intensity = 0.5 ** (age_h / half_life)
```

| 情绪类型 | 半衰期 | 理由 |
|---|---|---|
| `calm` / `soft` / `tired` | 3 小时 | 持久的心情，慢慢散 |
| `angry` / `shy` / `tsundere` | 1.5 小时 | 短暂情绪，来得快去得快 |

- 强度低于 **0.35** 自动回落到 `calm`
- `blend()` 换情绪时保留惯性（新强度 ≥ 0.6），避免一句话情绪跳变
- 注入 prompt 时会带强度描述：「有点害羞（残留，快消退了）」

这样「刚吵完架」和「昨天吵过架」是两种状态，不需要额外状态机。

## 4. 记忆打分（P1b）

### 问题

原来只按关键词重叠度排序，两个明显缺陷：

- 三年前的闲话和昨天说的偏好同权
- 「她讨厌下雨」（事实）和「今天聊了天气」（流水账）同权

### 新公式

```
score = 重叠度 × (0.55 + 0.45 × 新鲜度) × (0.6 + 0.4 × 类型重要度)
```

| 维度 | 计算 |
|---|---|
| 新鲜度 | `0.5 ** (age_days / 30)`，30 天前的记忆权重减半（不归零） |
| 类型重要度 | `fact=9` / `preference=8` / `event=6` / `summary=5` / `mood=4` |

另外两个约束：

- **去重**：近似重复的记忆只留分数最高那条
- **字数预算**：`build_memory_block` 默认 800 字，`MEMORY_MAX_CHARS` 可调
  （不限的话长对话后 prompt 会被记忆撑爆，token 成本和延迟都会涨）
- 召回条数 `MEMORY_K` 默认 6

## 5. 三层人格（P3）

| 层 | 文件 | 谁能改 | 说明 |
|---|---|---|---|
| L1 核心人格 | `persona/yukino.json` | 谁都不该随手改 | 决定她是谁 |
| L2 主人补充 | `persona/rules/owner.md` | 主人 | 补充规矩 |
| L3 相处偏好 | `persona/rules/self.md` | 她自己（需先问主人） | 相处偏好、当下目标 |

注入顺序 L1 → L2 → L3，**冲突以核心为准**（模板里也写明了）。

### L3 为什么要设三道闸

「让模型改自己的提示词」很容易失控：几轮之后规则膨胀成几百行，把人格挤没了。
所以强制：

1. 最多 **40 行**（超了拒绝写入）
2. 每行**自动带日期**
3. 必须 `append_self_rule(..., allowed=True)` 才能写 —— 对应「先征得主人同意」

## 7. 参数速查

```ini
# .env
QQ_STICKER=1          # 表情包开关
QQ_TEXT_PARTS=3       # 回复最多拆几条
QQ_TEXT_GAP=0.6       # 条间隔（秒）
QQ_PAUSE_MS=180       # 语音停顿压缩上限（80 紧凑 / 180 从容）
QQ_VOICE=1            # 语音开关
QQ_MAX_VOICE=2        # 每条消息最多几条语音
MEMORY_K=6            # 记忆召回条数
MEMORY_MAX_CHARS=800  # 记忆注入字数预算
```

## 8. 记忆写回（已接入定时任务）

`app/memsum.py` 每 2 小时跑一次（计划任务 `YukinoMemory`），把新对话压成长期记忆。

### 四个必须做对的点

1. **增量游标**：`meta.memory_summary_until_id` 记录已摘要到哪一条 turn，
   每次只处理 id 更大的。重复跑不会产生重复记忆，跑得再勤也只是空转。
2. **类型化提取**：提示词要求输出 `事实|…` / `偏好|…` / `事件|…`，
   解析后分别存 `kind=fact/preference/event` —— 直接喂给第 4 节的重要度打分。
3. **三态结果**（踩过的坑）：
   | status | 含义 | 游标 |
   |---|---|---|
   | `ok` | 解析成功（可能全是重复） | 推进 |
   | `nothing` | 模型明确说「无」 | **推进** |
   | `unparsed` | 输出跑偏 | 不推进，下次重试 |
   | `error` | API 异常 | 不推进 |
   一开始把「没输出条目」一律当失败，结果模型答「无」时游标不推进，
   每 2 小时重试同一批空对话，白烧 API。
4. **并发保护**：定时任务和机器人服务同时访问同一个 SQLite 文件，
   `busy_timeout` 提到 15 秒，避免 `database is locked`。

### 实测（真实 DeepSeek）

输入 3 轮合成对话：

```
事实|用户叫小明，在一家游戏公司做前端开发
事件|用户最近在学日语，准备明年去日本
偏好|用户特别讨厌下雨天，下雨会心情很差
```

→ 正确解析为 `fact` / `event` / `preference` 三条并落库。

生产库上的 8 轮测试对话都是寒暄，模型答「无」→ 游标推进到 id=8，不再重试。

## 9. 时间轮与人生经历

### 9.1 为什么年龄不能写死

写死「18 岁」的话，一年后她还是 18 岁 —— 一开口就露馅，比任何语气问题都出戏。

所以人格卡里只存两样东西，年龄每次现算：

```json
"life": { "birthday": "01-03", "birth_year": 2008 }
```

```
age = 当年 - 出生年        （今年生日还没到，再减 1）
```

界面和系统提示里都是实时值：

| 日期 | 年龄 | 提示 |
|---|---|---|
| 2026-10-30 | 18 | 你现在 18 岁。 |
| 2026-12-28 | 18 | 你现在 18 岁。还有 6 天就是你的生日（1 月 3 日）。 |
| **2027-01-03** | **19** | 今天 1 月 3 日是你的生日 —— 从今天起你 19 岁了。 |
| 2027-01-04 | 19 | 你现在 19 岁。 |

生日当天就长一岁（不用等第二天），代码里没有任何需要手动更新的地方。

`app/llm/lifecycle.py` 提供：

- `Life.from_dict()` 解析生日（支持 `01-03` / `1-3` / `01/03`）
- `age_on(day)` / `next_birthday(day)` / `snapshot(today)` 
- `render_age_hint()` 给 prompt 的一句话
- `render_life_block()` 渲染人生经历（带字数上限）

`/api/state` 也会返回 `age / birthday / is_birthday / days_to_birthday`。

### 9.2 18 年人生经历

故事线按**没有八幡**的世界写：她没有遇到那个人，奉仕部是她一个人创办的，
所以她更孤僻、也更靠自己。

结构上分五块，全部压成简短条目注入 prompt（约 1.6k 字上限）：

| 块 | 内容 | 作用 |
|---|---|---|
| `summary` | 一段总述 | 给模型一个人物底色 |
| `timeline` | 0~18 岁，18 条 | 被问到时能说出具体的年纪和事 |
| `family` | 父亲（县议员）、母亲、姐姐陽乃 | 家族压力是她性格的根 |
| `likes` / `dislikes` | 红茶、书、猫、熊猫周边… | 日常话题的抓手 |
| `private` | 不会主动说、被问到会承认的事 | 层次感（怕一个人、没交过朋友…） |

**披露策略**（写在 `note` 里）：

> 不要主动长篇讲述；被问到且对方问得真诚具体时，**给一点点具体细节**（一句就够），
> 但绝不全盘托出、绝不主动诉苦。不要编造年表之外的重大事件。

实测效果（好感度 12 / 低）：

```
用户：你喜欢什么东西？
雪乃：紅茶と、本と、あとは……猫。それ以上は、自分で観察してちだい。
      （红茶、书，还有……猫。剩下的，自己观察吧。）

用户：你小学的时候，过得开心吗？
雪乃：……楽しかったかどうか、今さら意味があるのかしら。
      第一、あなたに話すようなことでもないわ。
      （……开不开心，事到如今还有意义吗。再说，也不是该对你说的事。）
```

—— 喜欢的东西直接讲了（年表数据），过去则留一手。低好感度下这样是对的，
好感度上去后 `bands` 会把语气调软，她才会慢慢说更多。
