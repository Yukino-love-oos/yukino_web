## ⚠ 实施后的修正（本节优先于下文）

本文档写于动手之前，实施过程中有若干判断被实测推翻。**以本节为准**，下面对应的旧内容保留作为记录。

| # | 原文说法 | 实测结论 |
|---|---|---|
| 1 | `SoVITS_weights/default.pth` 是雪乃的 SoVITS 权重 | ❌ **错**。那个 517 MB 的 `default.pth` / `YUK95.pth` 是 **so-vits-svc** 模型（证据：配 `kmeans_10000YUK95.pt`，`YUK.json` 里有 `ssl_dim`/`gin_channels`/`spk`，且 pickle 键名是 svc 结构）。GPT-SoVITS 加载不了，`weight.json` 里 `"SoVITS": {}` 空着就是这个原因。 |
| 2 | 可用的权重是 default.pth | ✅ 正确的配对是：`GPT_weights/default.ckpt` + `SoVITS_weights/Yukino_Strong.pth`（强语气）；`GPT_weights/Yukino_Weak-e25.ckpt` + `SoVITS_weights/Yukino_Weak_01.pth`（弱语气）。权重训练于 2024-05，属 **v2** 世代，不是 v2Pro。 |
| 3 | 要改 `tts_infer.yaml` 的 `v2Pro` 段 | ❌ 不必。`TTS_Config` 用 `configs.get("custom", configs["v2"])`，**`custom` 段优先级最高**，而它本来就是 `device: cuda / is_half: true / version: v2`。真正要做的是把 `custom` 的权重路径指到雪乃权重。 |
| 4 | `prompt_text` 用 `あなた、いきなり姉さんのことを言い当てるから驚いたわ。` | ❌ 与参考音频不符。正确是 `あなたいきなり姉さんのこと言い当てるから驚いたわ。`（取自音频文件名即原作者转写）。不一致会导致音色漂移。 |
| 5 | `text_split_method: cut5` | ❌ 客户端已按句切好，再用 cut5 让服务端二次切句会产出 `なら、。` 这类垃圾。**用 `cut0`**。 |
| 6 | 流式直接用即可 | ⚠️ 三个坑：① `streaming_mode` 返回的 WAV 头里 `data` 长度写 0，播放器当空音频，需 `fix_wav_header()` 回填；② 纯标点碎片（如只有一个 `…`）会被服务端以「请输入有效文本」拒绝并断连，需 `is_speakable()` 过滤；③ **流式会关闭服务端并行推理与分桶处理，整句总耗时反而更长**（非流式 2.3s vs 流式 mode1 3.0s / mode3 4.0s）。在「整句收完再播」的架构下应**关闭流式**。 |
| 7 | 未提及 | 🔴 `import librosa` 时 numba 要往缓存目录写测试文件；目录只读时进程**静默卡死**（不报错）。必须设 `NUMBA_CACHE_DIR` 到可写目录。 |
| 8 | 未提及 | 🔴 PowerShell 脚本若无 BOM，Windows PowerShell 5.1 按 ANSI 读，中文注释直接导致解析失败。`.ps1` 一律存 UTF-8 **带 BOM**。 |
| 9 | 方案里让应用层用 openai / pydantic / requests | ✅ 实际改为**标准库实现**（urllib + SSE、手写 .env 解析、sqlite3），因为构建环境无法访问 PyPI。好处是少依赖、可离线自测。唯一强依赖是 streamlit。 |

实施结果：

|---|---|
| 语音链路 | ✅ 打通，32 kHz 单声道 WAV，非静音 |
| 端到端首响 | ✅ 1.35 ~ 1.86 s（mock LLM + 真实 TTS） |

| 单元测试 | ✅ 58 个全绿 |

## 0. 现状诊断（技术债清单）

按严重程度排序。P0 = 功能根本不通，P1 = 可维护性，P2 = 体验。

### P0-1　语音链路是断的（最致命）

代码里三处对不上，导致「对话有声」这个核心功能实际不工作：

| 环节 | 实际 | 代码里的假设 | 后果 |
|---|---|---|---|
| 启动脚本 | `startAPI.bat` → `runtime\python.exe api.py` | 以为是 `api_v2.py` | 两套参数名完全不同 |
| 参数名 | `api.py` 要 `text_language` / `prompt_language` / `speed` | `yukino_web.py` 发 `text_lang` / `prompt_lang` / `speed_factor` | 参数被忽略 → 报错 |
| 参考音频 | `api.py` 必须给 `refer_wav_path`（或启动时 `-dr`） | 代码里**完全没传**，`startAPI.bat` 也没有 `-dr` | `default_refer.is_ready()` 失败 → 返回非 200 |
| 结果 | `yukino_say()` 拿到非 200 → `return None` → 静音 | — | **永远没有声音** |

`api.py` 实际接受的参数：`refer_wav_path` `prompt_text` `prompt_language` `text` `text_language` `top_k` `top_p` `temperature` `speed` `cut_punc` `inp_refs`。
`api_v2.py` 实际接受的参数：`text` `text_lang` `ref_audio_path` `prompt_lang` `prompt_text` `text_split_method` `speed_factor` `media_type` `streaming_mode` …（无 `spk`）。

也就是说 `yukino_web.py` 是照着 `api_v2.py` 写的，但启动的却是 `api.py`，而且两边都缺 `ref_audio_path` / `refer_wav_path`。

### P0-2　API Key 明文泄露且已推送到 GitHub

```python

```

### P0-3　依赖环境与代码不匹配，无法复现

`yukino_brain/venv` 是 **Python 3.14.3**，装了 42 个包，全是 Google 系（`google-genai` `google-generativeai` `google-api-python-client` `protobuf` …）。
**没有 `openai`、没有 `streamlit`、没有 `torch`。**
→ `yukino_web.py` 在这个 venv 里一行都跑不起来。这个 venv 大概是当初试 Gemini 留下的，与现在代码无关。

另有：`yukino_voice/.../runtime` 是 **Python 3.9.13**（整合包自带，独立可用，不要混用）。

### P0-4　Git 仓库被撑到 10 GB

- 只有 1 个 commit `first commit`，把 22 GB 整合包 + 1347 个音频切片全提交了
- `.git` 单 pack **9.56 GiB**，外加 198 MB garbage
- 工作区里已删除的 `雪之下雪乃95%--B站id：Hiki老师.zip` 仍留在历史里

### P1-1　输出解析极脆弱

```python
display_text = full_res.rsplit("|", 1)[0] if "|" in full_res else full_res
japanese_part = re.split(r'[\(\[\{（【]', display_text)[0].strip()
```
- 只切**第一个**括号 → 句中一旦出现括号，括号后的日语会漏进 TTS
- 用 `|` 做分隔符 → 模型正常说话里出现竖线就误判
- 好感度解析 `except: pass` 静默吞错，扣分静默失败
- 中文翻译、动作描写、台词混在一个字符串里靠正则拆 —— 每次换模型都可能崩

### P1-2　好感度是全局变量，不持久化

`affinity = 0` 是模块级变量。CLI 版（`yukino_chat.py`）和 Web 版（`yukino_web.py`）各维护一份，逻辑还不一样（一份用 `[AFFINITY_CHANGE: N]`，一份用 `| N`）。重启即归零，没有历史记录，无法做任何成长曲线。

### P1-3　路径硬编码

```python
base_path = r"D:\Yukino\yukino_voice\GPT-SoVITS-v2pro-20250604"
YUKINO_IMG_PATH = "images/yukino_waifu.png"   # 依赖 cwd
```
换机器 / 换盘符即报废。`images/` 还是相对 cwd 的，从别的目录启动就找不到立绘。

### P1-4　无记忆

`st.session_state.messages[-10:]` —— 只保留最近 10 轮。刷新页面全丢。雪乃人设里「记得你说过的话」是体验核心，现在是零。

### P2-1　高延迟

当前链路：LLM 一次性生成全文（2–4 s）→ 整段日语送 TTS（1–3 s）→ 才开始播放。首包延迟约 **3–8 秒**，对话节奏完全断。

### P2-2　只能打字，不能说话，不能打断

没有 ASR，没有 VAD，`<audio autoplay>` 播起来就无法停止。

### P2-3　立绘是静态 PNG

`images/yukino_waifu.png` 一张图，无表情、无口型、无动作。好感度变化只影响侧边栏数字。

### P2-4　约 2 GB 冗余

### 2.2 修通语音链路（推荐方案 A）

**方案 A（推荐）：改用 `api_v2.py`，因为它支持流式，是降延迟的前提**

`yukino_voice/startAPI.bat` 改为：
```bat
@echo off
cd /d %~dp0
runtime\python.exe api_v2.py -a 127.0.0.1 -p 9880 -c GPT_SoVITS\configs\tts_infer.yaml
pause
```

`tts_infer.yaml` 的 `v2Pro` 段要确认 `device: cuda`、`is_half: true`（当前是 `cpu`/`false`，会很慢）。

启动后由客户端加载雪乃权重（一次性）：
```python
requests.get(f"{BASE}/set_gpt_weights",    params={"weights_path": "GPT_weights/default.ckpt"})
requests.get(f"{BASE}/set_sovits_weights", params={"weights_path": "SoVITS_weights/Yukino_Strong.pth"})
# 注意：不是 default.pth —— 那个是 so-vits-svc 模型，见开头「实施后的修正」#1
```

合成请求（`/tts` 同时支持 GET 与 POST）：
```python
payload = {
    "text": ja_text,
    "text_lang": "ja",
    "ref_audio_path": str(REF_AUDIO),        # ← 之前缺的就是这个
    "prompt_text": PROMPT_TEXT,              # 必须与参考音频内容逐字一致
    "prompt_lang": "ja",
    "text_split_method": "cut0",             # 客户端已按句切好，不要再让服务端二次切
    "batch_size": 1,
    "speed_factor": 1.0,
    "top_k": 5, "top_p": 1.0, "temperature": 1.0,
    "repetition_penalty": 1.35,
    "media_type": "ogg",                     # 流式建议 ogg
    "streaming_mode": True,
}
resp = requests.post(f"{BASE}/tts", json=payload, stream=True, timeout=60)
```

**方案 B（保守）：继续用 `api.py`**
只改 `startAPI.bat` 加参数，并修正客户端参数名：
```bat
runtime\python.exe api.py -dr "..\yukino\Yukino\参考音频\001.あなたいきなり姉さんのこと言い当てるから驚いたわ.wav" -dt "あなたいきなり姉さんのこと言い当てるから驚いたわ。" -dl ja -d cuda -p 9880
```
客户端把 `text_lang→text_language`、`prompt_lang→prompt_language`、`speed_factor→speed`、删掉 `spk`。
代价：`api.py` 流式支持弱（只有 `-sm` 整段分块），首包延迟压不下来。

> **建议先用 `curl` 手测一次**，确认拿到 200 + 音频字节，再动上层代码。

### 3.2 输出协议（**最关键的一次改动**）

放弃 `|` 和括号正则。改为**带标签的行协议**，既稳健又能流式解析：

```
<ja>それはどうかしら。あなたがそう思うなら、そうなんでしょうね。</ja>
<zh>那可不好说吧。既然你这么认为，那就这样吧。</zh>
<act>合上书，微微挑眉</act>
<mood>tsundere</mood>
<aff>-2</aff>
```

解析器 `app/llm/protocol.py`：
```python
import re
from dataclasses import dataclass, field

TAG = re.compile(r"<(ja|zh|act|mood|aff)>(.*?)</\1>", re.S)
OPEN = re.compile(r"<(ja|zh|act|mood|aff)>(.*)$", re.S)

@dataclass
class Turn:
    ja: str = ""
    zh: str = ""
    act: str = ""
    mood: str = "calm"
    aff: int = 0
    _seen: set = field(default_factory=set)

    def feed(self, chunk: str) -> list[str]:
        """喂入流式片段，返回可以立即送去 TTS 的完整日语句子。"""
        ...
```

**为什么不直接用 JSON mode**：JSON 必须等整个对象闭合才能用，与「边生成边播」冲突。标签协议让你可以在 `</ja>` 一出现就立刻合成 —— 这是把首包延迟从 3 s 压到 1 s 的关键。

同时保留 `--json` 模式供不对延迟敏感的场景（例如批量生成台词）。

好感度打分逻辑跟人设卡绑定，规则命中即写入 `turns`，便于随时回放「为什么扣分」。
防刷分从「提示词求模型自律」升级为「代码强制」：同一话题重复计数在 `app/state/session.py` 里算，再作为事实告诉模型。

### 3.4 低延迟流式链路

```
用户输入
   ↓
LLM(stream=True) ──► 标签协议增量解析
   ↓ </ja> 一到
按 。！？ 切句 ──► 送 api_v2 /tts (streaming_mode=True) ──► 边收边播
   ↓
同时解析 </mood> 换立绘表情、</aff> 更新好感度
```

三个关键点：
1. **LLM 流式**：`stream=True`，不要等全文
2. **句级 TTS**：一句一合成，不要整段
3. **音频缓存**：`hash(text + voice_params) -> ogg`，日常寒暄（「そう」「もう」之类）命中率会很高，直接零延迟

`app/tts/cache.py`：
```python
import hashlib, pathlib
CACHE = pathlib.Path("data/tts_cache")

def key(text: str, params: dict) -> str:
    raw = text + repr(sorted(params.items()))
    return hashlib.sha256(raw.encode()).hexdigest()

def get(text, params) -> bytes | None: ...
def put(text, params, audio: bytes) -> None: ...
```

### 3.5 语音输入与打断

- ASR：`faster-whisper` `small` 或 `medium`，int8，`language="ja"`；4060 Laptop 8 GB 富余。想更轻可用 SenseVoice-Small。
- VAD：`silero-vad`，检测到用户开口立刻：
  1. 停止播放（`player.stop()` 清队列）
  2. 取消当前 LLM 请求（`httpx` 的 `cancel` / 关掉生成器）
